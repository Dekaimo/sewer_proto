# 制作ルール（全キャラ・全場面共通）

キャラ別の行動仕様は各キャラのメモ（例：`docs/ドーベルマン_行動仕様と必要な絵.md`）に書き、ここには全体に効くルールだけを書く。行は増やさず、当てはまる項目を直してまとめる。

## 絵を見せる前のチェック（5項目で固定）
`python3 tools/check_asset.py 候補.png 基準の立ち絵.png 比較.png` を実行し、比較画像（明るい背景＋水色の背景）を大きく見てから、報告に5項目それぞれのOK/NGを書く。NGがあれば「できた」と言わない。**「見た」と書くだけで実際に見ていないチェックは無意味。** 単体の絵だけでなく、ゲームと同じ重ね方・位置で合成した絵を拡大して見る。腕の長さ・位置・動きの大きさ（何ドット動くか）・コマ間の差は数値で測って報告する。
1. **顔**：立ち絵から特徴を変えない（目・鼻・口の形と色）。猫は鼻が小さく暗い灰色でほとんど目立たない、紫の目。表情はオーバーにしない。**猫の表情の基準は `assets_raw/cat_face_ref_closed.png`**（目は細い弧で閉じる、口は小さく閉じたまま、歯・涙・大きく開けた口なし。このくらいの可愛い表情）。泣き顔・歯を食いしばる顔・頬染めはやりすぎ（ユーザーが場面ごとに「涙少し」等を指定したときだけその分を入れる）。**表情を変えるときも顔の線は立ち絵と同じ細さ・数のまま（シワ・影の線を足して顔を濃くしない）。生成の指示に「ギュッと」「シワ」「嘲笑」など強い言葉を入れると線が濃くなる。笑った目を記号（上向きの弧）にしない。** 敵のニヤけ（薄ら笑い）は立ち絵 `assets/dobe_idle.png` と同じ描き方（細い口の線の端を持ち上げ、少し離れた所に短い頬のシワ。「＜」のような漫画の記号は描かない）。舌なめずりは舌が上唇をなぞる程度。
2. **向き**：場面で決めた向き（猫の立ち絵 `assets/cat_0.png` は右向き。左向きが要る場面は左右反転してから作る）。**見ている角度から見えないはずの物を描かない**（後ろから見ているのに口が見える、取り込まれた後に帽子が外に出ている、隠れているはずの手が見える、等）。
3. **大きさ**：256×256以内（アニメはどれも上限256。余白を足して広げない）。体の高さ・幅は立ち絵と同じ（外枠でなく体で比べる）。腕などは伸ばさず、元の絵と同じ長さか数値で確かめる。
4. **透け・色**：透過し忘れ・抜きすぎが一切ない。編集（editv2）は白い背景、アニメは灰色の背景で描くので、白目・ツヤ・灰色に近い模様が抜けやすく、輪郭に灰色のふちも残る → `tools/fill_holes.py`（抜けたツヤを raw の色で埋め、灰色のふち・浮いた点を消す。背景色そのものの所だけが本当の隙間）→ 色合わせ → `tools/fill_small_holes.py`（輪郭に囲まれていない小さな穴＝抜けたツヤを埋める）。プレビューで気付かない穴がゲームの中で見えることがあるので、この順で必ず通す。層を色で切り出すときは、影・ハイライト・輪郭の色まで残す。生成で色が赤・紫・暗めにずれたら `tools/hue_fix.py`・`tools/palette_lock.py`・`tools/head_bright.py` で柱（ワニ）や立ち絵の色に合わせる（ガビガビ・黒ずみ・頭だけ暗い、も色のずれ）。
5. **つながり**：前後のコマ・重ねる相手と形・色・位置がつながっている。**生成で頼んでいない物（塊・歯・目・手など）が足されていないか、元の絵と比べる。** 動かないはずの所（下半身・腕・柱に付いた所）が毎コマ1〜3ドットずつガタついていないか、動かない部分で位置合わせして測る。ループは隣のコマとの差を全組で測り、ほぼ同じコマが続く所（止まって見える）がないこと。2つの層が掛け合う動き（押す⇄押される等）は同じコマ番号・同じ速さで合わせる。

## 進め方の決まり
- **指摘を受けたら、作る前に「何をしたいのか」を自分の言葉で言い直して確かめる。** 今後の予定（例：後でワニ自体をアニメさせる）と両立する方法を選ぶ。見た目だけ合わせた別の仕組み（絵全体の平行移動で「しなり」の代わりにする等）にしない。
- **送られた参考画像は必ず開き、作る絵と横に並べて比べてから作る。** どの部分（目か口か、動きか形か）の参考かを取り違えない。
- 指摘を受けて直すときは、前の指摘と今の指摘の両方を満たす形にする（却下済みのものを候補に戻さない）。直すたびに前の良かった所が崩れていないか比べる。
- **表情・場面の流れなど見た目の方向を決める生成は、先に既存の絵（基準の顔や他の場面）と並べて見せ、許可を取ってから行う**（ユーザーが「作っておいて」と任せたときは解釈を書いて進め、後でまとめて見せる）。「後で直す」と言われたものは、そのアニメを作る直前に必ず入れる。
- ファイル名を挙げるときは、その絵も一緒に見せる。
- 最後に良かった状態を常に残しておき、作業が途中で止まっても壊れた状態のまま放置しない（戻すなら確実に戻し、今どの状態かを書く）。
- 確かめられなかった所（smoke で届かない場面、効果音の聞こえ方など）は「確認済み」と書かず、未確認として報告する。
- 返答は日本語だけ。英語で返答しない。「その通りです」「おっしゃる通りです」などの同意の決まり文句を使わない。（リポジトリの `.claude/settings.json` のフックで、英語と決まり文句を自動で止めて書き直させる）

## 作り方の決まり
- ポーズは新規生成でなく、立ち絵（決定稿）からのアニメや編集で作る（新規生成は顔・向き・大きさが崩れる）。一度に1か所だけ変える。大きな変化は小さな変化に分けて重ねる。**顔が隠れた絵と顔が見える絵のあいだをアニメに任せると、途中のコマで顔が漫画調に崩れる**（振り向いた顔は立ち絵の頭を載せて編集で整えた決めコマを作り、決めコマ同士をアニメでつなぐ）。アニメは姿勢の切り替わりが1〜2コマに偏りやすい。
- 奥行き（手前・奥へ倒れる）の動きは骨格では付かない。体の倒れ方はアニメ生成で出し、顔だけ決めコマの頭に差し替える。「のけぞる」「倒れる」は横に伸ばすのでなく前後の動き。
- 「微か」「少しだけ」の動きはドット数で決めて測る（目安：上下は2〜4ドット以内）。強すぎ・速すぎ・大きすぎは毎回指摘されているので、迷ったら小さく。同じ指示で数本作り、測って一番合うものを選ぶ。
- 形を細かく指定しすぎると不自然になる（取り込まれた後に輪郭を出す→ぶつぶつ・変な形）。曖昧でいい所はアバウトに。
- 編集（editv2）の参考画像が元の絵とほぼ同じだと、出力が参考画像に戻る。
- 一連の動きは1本のアニメ（前のコマの続き）として作る。戻る動きは逆再生せず別に生成する。
- 主人公と敵を重ねる場面はレイヤーを分ける（奥の敵／主人公／手前の粘液／便乗する敵）。重ねる層は、奥の敵を青く塗り替えた絵に編集をかけ、色で切り出す（`tools/extract_goo.py`、磔の場面は `tools/cru_scene.py`）。もがきなど動く主人公に付いた粘液は主人公の絵に焼き込み、手首・足首などの固定の粘液だけを手前の層にする。揺れ・しなりは、しなる部分だけを曲げ、その上に乗っている物は付け根に乗ったまま傾ける。
- 粘液はしっかりドロドロ・下に垂れる。糸は重さで垂れ下がって途中が細くなる（網目・宙に浮く・上へ伸びる糸は不自然）。キャラの体を隠す帯・ベルトのようにはしない。コードで描く粘液表現は使わない。**手動の継ぎはぎ・手打ちのドットで目や口や粘液を描き足すのは絶対にNG（透明の穴を塗る・浮いたかけらを消す程度だけ可）。** 生成がだめなら生成し直す。
- 生成の指示に直接的な言葉を入れると規約で弾かれるので言い換える。生成回数は無駄にしない。
- ゲームに入れる前に明るい背景のGIFで見せる。
- コードを変えたら、Webビルドのログで「SCRIPT ERROR / Parse Error」が0件か確認する。GDScript は型が決まらない値に `:=` を使わない。
- アニメは溜め・詰めを控えめに。**ループには溜め・止まりを入れない**（常に動き続ける）。登場は4秒以内。

## ゲーム全体の調整
- ダメージ：長く弄ばれるように、捕まっている間 ×0.3、それ以外 ×0.6、汚れの上乗せ最大 ×1.25（`player.gd` の RESTRAINED_DMG / HIT_DMG / DIRT_DMG）。
- 動作確認：`.github/workflows/smoke.yml`（inputs.solo：0=全部 / 1=ドーベルマンだけ / shark / hd / hds / cru）で画面なし60秒実行し、状態とエラーをログに出す。cru は抵抗失敗後（擦りつけ・飲ませる）まで届かないので、そこはゲームで目視が必要。
- 効果音：全体的に濡れてグチョグチョした音（`tools/gen_sfx.py`）。既にある音は飛ばされるので、作り直すときは消してから `gen_sfx.yml`。
- 穴だらけになる原因：PixelLab は灰色の背景の上に描き、キャラの内側でも背景色で塗る所がある。対策は `tools/pixellab_anim.py` の remove_bg（外枠からつながる背景と、内側の背景色の塊だけを抜く）。
- 生成ジョブの後は `git pull` で衝突しやすい（ワークフローが同じブランチに書き込む）。先に自分の変更をコミットしてから取り込む。
